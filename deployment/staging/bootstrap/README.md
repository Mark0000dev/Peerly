Its policies array is empty. `policies.v1.json` contains authored, versioned English Terms/Privacy for internal staging, with the public contact taken from the owner's supplied Reply-To address. Validate both inputs offline and explicitly publish them before signup; neither file is automatically seeded by application startup.

The starter catalogue contains ten broad knowledge areas. It supports self-declared help across course boundaries; module codes remain optional task context. Genuine language/name synonyms are included as aliases. Course codes such as IDB, SSCC and BMK2 are not aliases for broader knowledge areas. UUIDs are stable application identifiers, not university module IDs. This small catalogue can be expanded through an explicit new version as the pilot needs become clearer.

Version `peerly-knowledge-areas-2026-11-09-v1` becomes immutable on publication. If a reviewed list expands or corrects it, supply a new explicit version and retain existing identities where the meaning is unchanged. The earlier course-name-only proposal was never imported into a live database and is superseded by the approved product decision in the approved product decisions. Never rewrite published input in place.

Validate offline using the CLI before applying to the selected staging database. Applying is an explicit deployment operation; committing this file does not modify a database or grant any account access.

## Internal staging policy scope

The policies describe mandatory identified analytics, audited full operator access, soft deletion with internally retained history, compact registration acknowledgement and policy-only detailed disclosures. The drafts state these practices, describe optional AI/manual input separately, and preserve applicable rights rather than asserting that registration waives them. Support hours use the selected Malaysia-time09:00–21:00 window without a response-time guarantee.

Before publication, check the supplied contact and actual deployment/provider inventory. Before external student admission, finalise operator identity, provider locations/transfer assessment, applicable notice-language requirements, retention handling and the operational promises against the deployed service. An English internal staging document and technical implementation do not establish legal compliance. Preserve original registration versions; later changes require a new explicit document version.

Primary references consulted during authoring: Malaysia's Personal Data Protection Department [privacy guidance/FAQ](https://www.pdp.gov.my/en/faq/), [privacy notice guide](https://www.pdp.gov.my/ppdpv1/wp-content/uploads/2025/01/A-Quick-Guide-to-PRIVACY-NOTICE.pdf), and [cross-border processing guidance](https://www.pdp.gov.my/en/akta/personal-data-protection-guidelines-on-cross-border-transfer-of-personal-data-cbpdt/). These references do not imply regulator approval of Peerly.
