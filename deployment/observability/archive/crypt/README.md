# Native client-encrypted archive gateway (experimental)

This is a NEW opt-in layer; the original seven archive files remain immutable. Collector0.165.0 cannot set Cloud.ru per-object SSE-C/KMS headers. This gateway instead encrypts object contents and names with native rclone crypt before S3 transport. This is client-side encryption, not a claim about provider SSE. The actual provider bucket is `peerly-archive`, never the bucket-ID UUID.

Pinned rclone1.76.0 multi-platform image digest is `sha256:7cbeec24a44f206067597c0368be4de90ae19a64d5113c7d1938bd737a81e466` (official registry, release6 November2026). `serve s3` remains experimental. Native SigV4 and exact Collector SDK/checksum interoperability need the recorded synthetic proof and parent real readback; no custom signature middleware or crypto/app SDK.

Topology: existing sanitized Collector → dedicated internal `archive_crypto` network, authenticated HTTP → rclone `serve s3 encrypted:` → crypt → verified HTTPS Cloud.ru S3. No host port, application-network gateway membership, RC, file cache or anonymous fallback. Parent supplies a separate random gateway pair; these are the ONLY AWS credentials used by Collector. Cloud credentials and obscured crypt passwords stay in a private UID10001-owned read-only config at `/run/secrets/rclone.conf`. `RCLONE_AUTH_KEY` must be CSV-quoted exactly as documented (`"identifier,secret"`); never omit it. Parent must verify it matches the Collector pair and that unsigned/wrong signatures fail. No public clients. SigV4 authentication grants access to this entire isolated namespace, not a PUT-only ACL.

Use base + immutable `archive.compose.yml` + NEW `crypt.compose.yml` last. For remote-write also load its base overlay, then `archive/crypt/remote-write.compose.yml` last to preserve all four config arguments. The original archive Compose's required variables must still resolve; use gateway credentials for its legacy access-key placeholders, never Cloud credentials. Final Collector environment explicitly overrides them with the dedicated gateway variables. The original logical archive prefix remains a safe fixed non-user-controlled prefix inside virtual bucket `ingest`. Actual encrypted root is `raw:peerly-archive/crypt-v1`; do not mix raw gzip objects into this layout.

Parent writes the actual config from `rclone.conf.example`, using native `rclone obscure` for a generated high-entropy password and separate salt. Obscuring is reversible and NOT config encryption. Back up password, salt, full options, root mapping, pinned version/digest and config securely OFFLINE, independently of the gateway host. No encryption-key generation or real credentials by this developer. Losing those values loses decryptability; changing keys in place cannot decrypt old objects. Use a versioned root for deliberate future key changes.

Native virtual bucket `ingest` is a directory within crypt, not a new Cloud bucket. Empty S3 folders do not persist reliably. Parent must seed a small encrypted `encrypted:ingest/.gateway-format` marker using native `rclone rcat` before starting ingestion; this is the only bootstrap object. Never create/delete the actual Cloud bucket. Marker is encrypted by the same native crypt path and survives gateway restart. No automatic data deletion or TTL. Any abandoned multipart cleanup concerns incomplete writes only, not accepted archives.

Bounds:192MiB hard container limit/GOMEMLIMIT160MiB,0.2CPU/PID64; cache off, read buffers0, streaming cutoff1MiB, backend chunks5MiB/concurrency1, shared upload pool32MiB, max2 multipart uploads, reordered-parts caps5MiB/upload and10MiB/user, metadata128 objects, server15s read/write, connection5s/idle5s, retries1. These replace unsafe upstream defaults. Native inbound connection count is not capped; isolation plus two trusted Collector signal consumers is the operating assumption, not a hostile-client server guarantee. Container memory cap may still kill an overloaded gateway; durable Collector queues retain unacknowledged work within their finite limits.

With cache off, the native PUT path copies/encrypts and waits for close/remote completion before successful acknowledgement. Do not enable VFS writes/full or early asynchronous writeback. Upstream access must allow required prefix-scoped List/HEAD/PUT and applicable multipart operations; do not falsely advertise pure PutObject-only compatibility or disable HEAD integrity checks. Parent verifies Cloud.ru path-style/region/TLS/permissions and actual ciphertext readback. Archive UUIDv7 logical keys remain collision-resistant; encryption preserves deterministic lookup of names but creates randomized encrypted content. Ambiguous retries may duplicate records; no exactly-once guarantee.

## Synthetic proof and offline recovery

Run ONCE after source completion with both pinned images local:

```sh
node deployment/observability/archive/crypt/prove.mjs
```

The proof extracts native binaries, uses loopback endpoints and SYNTHETIC-only secrets in isolated temporary configs (no home AWS/rclone credential reads), and runs a native raw S3 server on a local directory plus the actual crypt gateway. A bounded transparent transport fixture creates an outage without modifying signatures. It checks unsigned/wrong authentication, native ciphertext magic rather than gzip/plaintext, persistent Collector SIGKILL recovery, restarted gateway/virtual bucket, four unique objects, offline native decryption with gzip hash equality, wrong-key and tamper failures with no plaintext, and existing native OTLP JSON restoration. No real provider or encryption keys. Host-binary proof does not establish kernel container resource isolation; compose rendering establishes intended policy only.

For real recovery parent downloads raw encrypted objects and encrypted paths from the scoped root, stops network access, then configures a LOCAL crypt remote over that downloaded ciphertext tree using the backed-up identical crypt options/password/salt. Native `rclone copy local-crypt:ingest/... offline-plain/` decrypts to the original `.json.gz` objects. Verify expected object hashes/counts/IDs, gunzip bounded approved selections, and use the immutable native `archive/restore.yaml` offline receiver. Do not point a restored receiver at the production archive exporter, run unbounded history replays, or infer completeness from a directory listing. No gateway or Cloud credentials are needed after ciphertext download.
